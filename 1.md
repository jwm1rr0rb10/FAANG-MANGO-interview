Что такое ООП?
Объектно-ориентированное программирование (ООП) — парадигма программирования, основанная на концепции «объектов», которые объединяют данные (состояние) и поведение (методы). Основные принципы (четыре столпа):
Инкапсуляция
Наследование
Полиморфизм
Абстракция

Как ООП сделано в Golang? / Как реализовано ООП в Go?
Go не является классическим ООП-языком (нет классов, нет наследования в привычном смысле).
Вместо этого Go предлагает лёгкую ООП-модель через:
структуры (struct) + методы → аналог объектов
интерфейсы (неявная реализация) → полиморфизм и абстракция
встраивание (embedding) → композиция вместо наследования
экспорт/неэкспорт полей и методов → инкапсуляция

Как реализовано наследование в Go?
Классического наследования нет.
Вместо него используется композиция + встраивание структур (embedding):Gotype Animal struct {
    Name string
}

type Dog struct {
    Animal          // встраивание → promotion методов и полей
    Breed  string
}Это композиция, а не наследование (нет is-a отношения в строгом смысле).
Что будет, если и в родительской, и в дочерней структуре есть методы с одинаковым названием?
Метод дочерней структуры перекрывает (shadows) метод встроенной структуры.
При вызове на типе Dog будет вызван именно Dog.Bark(), а не Animal.Bark().Чтобы вызвать метод встроенного типа — нужно явно: d.Animal.Bark().
Как реализована инкапсуляция в Go?
Через правила видимости на уровне пакета:
Имена, начинающиеся с заглавной буквы → экспортированы (public)
Имена с маленькой буквы → приватные (private, видны только внутри пакета)
Это самый простой и часто достаточный механизм инкапсуляции.
Как реализован полиморфизм в Go?
Через интерфейсы с неявной реализацией (duck typing):Gotype Writer interface {
    Write([]byte) (int, error)
}Любой тип, у которого есть метод Write, автоматически реализует Writer.
Это самый мощный и часто используемый полиморфизм в Go.
Как устроено инвертирование зависимостей (dependency inversion) в Go?
Высокоуровневые модули не зависят от низкоуровневых — оба зависят от абстракции (интерфейса).
В Go это достигается тем, что интерфейс определяет потребитель (consumer), а не поставщик (producer).
На какой стороне описывать интерфейс — на передающей или принимающей?
Почти всегда — на принимающей стороне (на стороне потребителя / клиента).Это один из самых важных идиоматических правил Go:
«Интерфейсы принадлежат потребителю» (interfaces belong to the consumer).
Как сделать свои методы для стороннего пакета (например, для Zap-логгера)?
Прямым способом нельзя — Go запрещает добавлять методы к типу, определённому в другом пакете.Решения:
type alias + свои методы (но теряются методы оригинала)
обёртка / декоратор (самый распространённый и рекомендуемый способ)
Gotype MyLogger struct {
    *zap.Logger
}

func (l *MyLogger) WithRequestID(id string) *MyLogger {
    return &MyLogger{l.With(zap.String("req_id", id))}
}
Что такое замыкание?
Замыкание (closure) — это анонимная функция, которая захватывает (запоминает) переменные из внешней области видимости, даже после того, как внешняя функция завершила выполнение.
Что такое захват переменной?
Это ситуация, когда анонимная функция внутри другой функции ссылается на переменные внешней функции.
Go захватывает их по ссылке (не копирует значение на момент создания замыкания).Классическая ошибка с циклом:Gofor i := 0; i < 5; i++ {
    go func() { fmt.Println(i) }()   // почти всегда выведет 5
}Исправление: передать копию как параметр или использовать локальную переменную.


Variant 2 — in English

What is OOP?
Object-Oriented Programming (OOP) is a programming paradigm based on the concept of objects that combine data (state) and behavior (methods). The four main pillars are:
Encapsulation
Inheritance
Polymorphism
Abstraction

How is OOP done / implemented in Golang / Go?
Go is not a classic OOP language (no classes, no classical inheritance).
It offers a lightweight OOP model using:
structs + methods → objects-like behavior
interfaces (implicit implementation) → polymorphism & abstraction
embedding → composition over inheritance
exported / unexported identifiers → encapsulation

How is inheritance implemented in Go?
There is no classical inheritance.
Instead Go uses composition + struct embedding:Gotype Animal struct {
    Name string
}

type Dog struct {
    Animal         // embedding → promoted fields & methods
    Breed  string
}This is composition, not inheritance (no strict is-a relationship).
What happens if both the "parent" and "child" struct have methods with the same name?
The method of the embedding (outer) type shadows / overrides the method of the embedded type.
Calling d.Bark() will call Dog.Bark(), not Animal.Bark().To call the embedded one explicitly: d.Animal.Bark().
How is encapsulation implemented in Go?
Via package-level visibility rules:
Capital letter at the beginning → exported (public)
Lowercase letter → unexported (private to the package)
This is the primary (and often sufficient) encapsulation mechanism.
How is polymorphism implemented in Go?
Through interfaces with implicit satisfaction (structural typing / duck typing):Gotype Writer interface {
    Write([]byte) (int, error)
}Any type that has a Write method automatically implements Writer.
This is the most powerful and idiomatic polymorphism in Go.
How is dependency inversion (Dependency Inversion Principle) arranged in Go?
High-level modules should not depend on low-level modules — both should depend on abstractions (interfaces).
In Go this is achieved by defining interfaces on the consumer side, not the producer side.
On which side should you define an interface — the caller / consumer side or the producer / provider side?
Almost always — on the consumer / caller side.This is one of the strongest Go idioms:
“Interfaces belong to the consumer” (not to the producer).
How to add your own methods to a third-party type (e.g. for zap.Logger)?
You cannot directly add methods to a type defined in another package (Go forbids it).Common solutions:
Type alias (but you lose original methods)
Wrapper / decorator struct (most recommended approach)
Gotype MyLogger struct {
    *zap.Logger
}

func (l *MyLogger) WithRequestID(id string) *MyLogger {
    return &MyLogger{l.With(zap.String("req_id", id))}
}
What is a closure?
A closure is an anonymous function that captures variables from its surrounding scope, even after the outer function has returned.
What is variable capture?
It happens when an inner (anonymous) function refers to variables from the outer scope.
Go captures variables by reference (not by value at creation time).Classic gotcha in loops:Gofor i := 0; i < 5; i++ {
    go func() { fmt.Println(i) }()   // usually prints 5 five times
}Fix: pass a copy as parameter or create a local variable inside the loop.
